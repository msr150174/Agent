# 路书 · 知识库引用变量名规范 v1.1

> 用途：给「路书」智能体的提示词、检索流程与数据库查询提供统一变量名，避免同一册知识库出现多种叫法。
> 编制日期：2026-11-12　｜　适用知识库：学科（3 专业）· 学校官网 · 心理安全 · 职业规划（清洗整合版）
> 与 v1.0 的关系：`KB_` 前缀与 FACT / ACTION / SUPPORT 三层**原样保留**，新增 `MAJOR` 专业层与 `TASK` 任务层；变量总数 54 个。

---

## 四、命名规则（8 条，新增册照此办）

1. 固定前缀 KB_，全大写，层名用英文单词（FACT / ACTION / SUPPORT / MAJOR），不用拼音缩写、不用 KB1/KB2 这类无意义序号。
2. 一册一个主变量；需要精确定位时再加章节子变量，不为主变量另起别名。
3. 变量名不带年份、不带版本号；年度口径写在变量定义里。
4. 专业层用专业代码作后缀（KB_MAJOR_510203），不用专业名拼音，避免改名与重名。
5. 变量值只写文件名 + 数据口径，不写本地路径或网盘链接。
6. 不新建内容型变量（如 KB_SALARY、KB_ZHUANSHENGBEN）；同一事实只允许一个出处。
7. 命中优先级：危机信号 → KB_SUPPORT（无条件优先）；专业培养/课程/学期 → KB_MAJOR_<代码>；岗位/证书/薪资/简历面试/权益 → KB_ACTION；学校类事实 → KB_FACT。
8. 变量内检索不到原文片段 → 直接答「现有资料未覆盖」，禁止拿另一个变量或通用常识补位。

## 五、命中优先级与兜底

```text
1) 出现自伤/轻生/极端情绪等危机信号 → 只用 KB_SUPPORT，先给红灯判断 + 求助路径，不谈职业规划。
2) 问「我这个专业学什么/第几学期学什么课/要考什么证/能不能专升本」 → KB_MAJOR_<专业代码>。
3) 问岗位做什么、要会什么、薪资多少、简历面试、三方/试用期 → KB_ACTION。
4) 问学校代码、学费、招生规则、资助、宿舍、部门电话 → KB_FACT。
5) 同一问题跨两层（如「我这个专业能投什么岗」）→ KB_MAJOR（专业口径）+ KB_ACTION（岗位口径），分别标注来源。
6) 任何一层拿不到原文片段 → 统一答「现有资料未覆盖」，并指向 gov_gap 里的建议确认部门，禁止用通用常识补位。
```

## 六、提示词里怎么引用

```text
检索顺序：专业培养/课程/学期 → {KB_MAJOR_<专业代码>}；岗位/技能/薪资/简历面试/权益 → {KB_ACTION}；
学校类事实 → {KB_FACT}；心理与危机 → {KB_SUPPORT}（危机无条件优先）。

回答涉及金额、日期、报名条件、名额、政策条款时，必须标注来源文件名与生效日期，例如：
以上信息来自《广州华南商贸职业学院_知识库》，主数据 2026 年版，请以官方最新通知为准。
软件技术专业另注：2026 级适用，文件未标注生效日期（制定日期 2026-05-30）。

任何变量都拿不到原文片段时，回答固定为：「现有资料未覆盖」。
```

数据库侧的等价写法（全文召回，`kb_search` 的 `seg` 列是逐字加空格的分词文本，查询要同样处理并加引号）：

```sql
-- 参数 :q 需先做「逐字加空格」处理，例如 学费 -> ' 学 费 '
SELECT s.doc_id, s.chapter_title, s.title, snippet(kb_search, 3, '…', '…', 24) AS 摘要
FROM kb_search f JOIN kb_section s ON s.sec_id = f.sec_id
WHERE f.seg MATCH '"' || :q || '"'
ORDER BY f.rank LIMIT 8;
```

## 七、禁止使用的旧叫法

| 不要用 | 原因 |
|---|---|
| 知识库1 / 知识库2 / 知识库3、KB1/KB2/KB3 | 顺序会随附件增减变化，无法自解释 |
| 学校库 / 职业库 / 心理库 混用作变量名 | 中文名可作口语称呼，但变量名必须是 ASCII 标识符 |
| KB_SCHOOL 与 KB_FACT 并存 | 同册两套名字，检索时容易漏检 |
| KB_MAJOR_软件 / KB_MAJOR_SE 混用 | 专业层统一用专业代码后缀，避免拼音与缩写两套叫法 |

## 九、变更流程

1. 新增一册 → 分配新层名（英文单词）→ 在 `gov_layer`、`gov_doc` 各加一行 → `gov_variable` 加主变量。
2. 新增专业 → 在 `maj_major` 加一行（专业代码即变量后缀），并补 7 个章节子变量。
3. 重跑 `build/build.py` → 跑 `build/export_docs.py` 重新生成本文件与映射文档，保证文档与库同源。
4. 版本号 +0.1，并把变更写进第八节。

> 本规范只定义变量名与调用规则；变量内容仍以四册知识库原文为准。
