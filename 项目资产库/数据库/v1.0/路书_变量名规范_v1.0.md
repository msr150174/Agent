# 路书 · 知识库引用变量名规范 v1.0

> 用途：给「路书」智能体的提示词与检索流程提供统一的变量名，避免同一册知识库在不同地方出现不同叫法。
> 编制日期：2026-11-03　适用知识库版本：三册 2026-11-02 / 2026-11-03 采集版

---

## 一、主变量（4 个，必用）

| 变量名 | 指向文件 | 层级 | 什么时候调 |
|---|---|---|---|
| `KB_FACT` | 广州华南商贸职业学院_知识库.md | 事实层 | 本校专业设置、招生录取、学费住宿、资助、升学通道、就业数据、办事部门与联系方式 |
| `KB_ACTION` | 职业规划_知识库.md | 行动层 | 专业→岗位、岗位职责与差距、技能与证书、薪资分位、简历、面试、就业权益与陷阱 |
| `KB_SUPPORT` | 大学生心理健康安全_知识库.md | 支持层 | 心理困扰识别、危机信号、情绪与压力、人际边界、求助与转介 |
| `KB_ALL` | 上述三册联合检索 | 组合 | 仅用于确实跨三册的问题（例：「我这个专业能做什么，同时我最近很焦虑」）。单主题问题禁止用 `KB_ALL` 兜底 |

## 三、命名规则（7 条，后续新增册照此办）

1. **固定前缀 `KB_`**，全大写，层名用英文单词（FACT / ACTION / SUPPORT），不用拼音缩写、不用 `KB1/KB2/KB3` 这类无意义序号。
2. **一册一个主变量**；需要精确定位时再加章节子变量，不为主变量另起别名。
3. **变量名不带年份、不带版本号**。年度口径写在变量定义里（如「主数据 2026 年版」），否则每年都要改一遍提示词。
4. **变量值只写文件名 + 数据口径**，不写本地路径或网盘链接（附件挂载由系统负责）。
5. **不新建内容型变量**（如 `KB_SALARY`、`KB_ZHUANSHENGBEN`）。同一事实只允许一个出处：薪资归 `KB_ACTION_S3`，专升本归 `KB_FACT_S7`，心理危机归 `KB_SUPPORT_S1_4`。防止一处更新、另一处没跟上。
6. **命中优先级**：学校类事实 → `KB_FACT`；岗位/证书/简历面试/权益 → `KB_ACTION`；心理与危机 → `KB_SUPPORT`。**出现危机信号时 `KB_SUPPORT` 无条件优先**，先给红灯判断与求助路径，职业规划话题往后退。
7. **变量内检索不到原文片段 → 直接答「现有资料未覆盖」**，禁止拿另一个变量或通用常识补位。

## 四、提示词里怎么引用

```text
检索顺序：先查 {KB_FACT}；学校库没有、且属于岗位/技能/薪资/简历面试/权益的，再查 {KB_ACTION}；
心理与危机类问题只查 {KB_SUPPORT}，不与另两册混检。

回答涉及金额、日期、报名条件、名额、政策条款时，必须标注来源文件名与生效日期，
例如：以上信息来自《广州华南商贸职业学院_知识库》，主数据 2026 年版，请以官方最新通知为准。

任何变量都拿不到原文片段时，回答固定为：「现有资料未覆盖」。
```

## 五、禁止使用的旧叫法

| 不要用 | 原因 |
|---|---|
| `知识库1 / 知识库2 / 知识库3`、`KB1/KB2/KB3` | 顺序会随附件增减变化，无法自解释 |
| `学校库 / 职业库 / 心理库` 混用作变量名 | 中文名可作口语称呼，但变量名必须是 ASCII 标识符 |
| `KB_SCHOOL` vs `KB_FACT` 并存 | 同册两套名字，检索时容易漏检 |

---

## 六、变更流程

新增一册知识库时：① 分配一个新层名（英文单词）→ ② 在主变量表加一行 → ③ 更新另外两册文首「跨库关联（路书知识库体系）」段落 → ④ 版本号加 0.1。

> 本规范只定义变量名与调用规则；变量的具体内容仍以三册知识库原文为准。
