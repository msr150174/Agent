## 四、字段映射（库表没有 x/y 坐标）

`gov_node` 的真实 schema 是：

```
node_id, node_type, node_name, zone, mount, io_in, io_out,
fail_text, verify_text, impl_node, sort_no
```

导出时这样对应：

| 库字段 | 画布来源 |
|---|---|
| `node_id` | 节点 id 原样 |
| `node_type` | id 前缀（DOC/SPEC/DATA/MATRIX/CONTRACT/SUB/FLOW/AGENT/QA） |
| `node_name` | 节点正文首行标题（去掉 `路书--` 前缀） |
| `zone` | 节点所在 group 的 label，用几何包含关系判定，不靠人填 |
| `mount` / `io_in` / `io_out` / `fail_text` / `verify_text` | 节点 `meta` 的 mount / in / out / fail / verify |
| `impl_node` | `meta.impl`（即真实实现节点） |
| `sort_no` | id 里的序号 |

`zone` 靠几何判定，所以**任何节点只要画错分区，库里就会立刻出现 `empty_zone`**——布局错误和数据结构错误被绑成了同一个信号。

## 六、变量合规：这次是真跑过的

铁律说「提示词只许引 `gov_variable` 里有的名字」，我把画布 44 个节点全文扫了一遍，与变量注册表做集合比对：

| 项 | 结果 |
|---|---|
| 注册变量总数 | 57（主变量 8 / 章节子变量 25 / 专业子变量 3 / 专业章节子变量 21） |
| 画布引用 | 14 个，全部命中 |
| **可执行节点中未注册引用** | **0** |

> 口径说明：校验范围是 34 个「可执行节点」（AGENT / FLOW / SUB / CONTRACT / MATRIX / INDEX-08），
> 排除 `DOC-71-CHANGELOG`——变更记录天然要写「原来错写成 `KB_MAJOR_*`」，那不是实际引用。

修掉的一个真问题：原文里 7 处写的是 `KB_MAJOR_*`。这是通配符，不是可执行变量名；而注册表里本来就有 `KB_MAJOR`（主变量，「三专业册联合检索」）。改成 `KB_MAJOR` 后，字面合规且语义等价。

## 七、一个不显眼但会出事的口径：马克思主义学院

`fact_college` 是 6 行，全是「二级学院」；华为 ICT 产业学院不在这张表里。所以：

- **学院总数 = 6 个二级学院 + 1 个产业学院 = 7 个**
- **画布上的学院提示词节点 = 6 个**（信息 / 经管 / 人文 / 卫健 / 设计传媒 + 华为ICT）

差的这 1 个是**马克思主义学院**。它不招专业、`fact_major` 里没有它的专业归属（G14），
如果照猫画虎给它建一个节点，会得到一个永远只会说「未覆盖」的空智能体。

所以这版的处理是**明确不建节点，但把落点写死**：

| 学生问到 | 落到 |
|---|---|
| 「马院有哪些专业」 | 回归属说明（该院不招专业）→ 转 `AGENT-58-COUNSEL` |
| 「思政课怎么安排 / 毛概谁上」 | 转 `AGENT-61-AFFAIR`（学校政务，授课安排归教务处） |

同时改掉了两个会指向空节点的写法：

1. 学院边界话术原来是「这属于〔XX〕学院，请找对应智能体」——现在**列出 6 个真实存在的转交名**，并注明马院不指向任何智能体。
2. 主智能体路由表补了一行「思政课 → 学校政务」，否则「马克思主义学院」会掉进兜底分支。

> 一句话记住：**「6 个二级学院」和「6 个学院节点」是两个不同的 6**，差的那一个是马克思主义学院。
