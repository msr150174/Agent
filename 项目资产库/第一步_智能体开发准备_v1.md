## 0. 本步完成的判定（Definition of Done）

五条全部满足才算完成，缺一条都别进第二步：

| # | 判定项 | 验证方式 |
| --- | --- | --- |

## 2. 素材准备（先深做 1 个专业，不做全量）

**原则：先做一个能讲透的样品，再复制。** 48 个专业两周做不完，先用 1 个专业（建议选信息学院或经济管理学院里招生最多的）把链路跑通。

最小知识库（能支撑演示即可）：

| 组 | 最小内容 | 数量 | 谁做 | 文件格式 |
| --- | --- | --- | --- | --- |
| A 专业与岗位 | 1 个专业的说明 + 6–8 个岗位 + 岗位技能要求 | 1 专业 / 8 岗位 | A | md |
| B 证书 | 该专业常见证书 | 5 条 | A | md |
| C 政策 | 专插本 / 考编 政策原文 | 5 篇 | A | md（含来源与生效日期） |
| D 简历面试 | 简历要点、常见面试问题 | 2 篇 | A | md |
| E 竞赛与考证 | 该专业适配的 5 个赛事 | 5 篇 | A | md（用已产出的 E 组数据） |

**Obsidian 笔记上传前必须清洗**（否则等于没传）：

| 处理 | 做法 |
| --- | --- |
| 双链 | 删掉 [[笔记名]]，改普通文字 |
| 图片嵌入 | 删掉 ![[图片]]，关键信息必须写在正文文字里 |
| 行内标签 | 转成 YAML 或删掉 |
| 标题层级 | 最多 3 级 |
| 一篇一主题 | 一个政策 / 一个岗位 = 一篇 |
| 元信息 | 每篇开头加 YAML：title / category / source / source_url / effective_from / verified_at |

## 3. 建项目：四个字段怎么填

| 字段 | 填什么 |
| --- | --- |
| **项目名称** | 路书 · 高职学生职业规划智能体 |
| **连接器** | 只勾 **乐享知识库**（或 IMA）。天眼查、CRM、TAPD、GitHub、Supabase、法研、微云一律不勾 |
| **专家** | 有教育/生涯规划/咨询类就选；没有就**留空**（留空比乱选好，避免预设人设覆盖你的规范） |
| **技能** | 只勾三项：知识库检索、文档解析、结构化输出。联网搜索、网页生成、代码执行、图片生成全部不勾 |

### 项目背景与规范（复制这段）

```text
【项目】路书 —— 高职学生职业规划智能体
【定位】用本校真实数据，帮高职学生从"不知道往哪走"走到"有一张走得完的路线图"。

【服务对象】广州市高职院校在校学生（16–21 岁），自己在手机或电脑上打开使用；不是教师后台工具。

【核心任务，只做这四件】
1. 认识自己：用 12 道简化自评题给出职业兴趣倾向（六类），只作自我探索参考。
2. 看清路：结合学生专业，说明本校该专业可去的岗位，以及就业 / 专插本 / 考编三条路径的差别。
3. 做路线图：生成按学期排列、可逐条勾选的行动清单。
4. 找比赛与考证：按"保底 / 主攻 / 冲刺"各推 1 个，给时间窗（学年 + 月份区间）与报名归口。

【事实规则（最高优先级，违反即视为错误）】
1. 专业、岗位、技能、证书、政策、薪资、赛事信息只能来自本项目挂载的知识库。
2. 知识库没有的，直接回答"现有资料未覆盖"，不得推测、不得用通用常识补充、不得用记忆里的政策条款。
3. 涉及金额、日期、报名条件、名额、政策条款，必须注明来源文件名与生效日期。
4. 政策类回答固定结尾："以上信息来自《文件名》，生效日期〔日期〕，请以官方最新通知为准。"
5. 回答前先在内部列出检索到的原文片段，再据片段作答；没有片段就不作答。

【输出规范】
1. 简体中文，先一句话给结论，再展开；单次回复不超过 250 字。
2. 岗位建议必须给"为什么推荐（2 条）+ 还差什么（1 条）"，理由要能被知识库支撑。
3. 分学期清单固定结构：学期 / 目标一句话 / 任务（可勾选）/ 对应证书或比赛。
4. 竞赛推荐只推 3 个，且必须给适配理由、时间窗、报名归口。
5. 不确定时统一说："我不确定，建议你向〔具体部门〕确认。"
6. 禁用绝对化表述：保证、一定、百分百、稳过。

【语气】像一个耐心、诚实的大三学长：不灌鸡汤、不堆术语、不替学生做决定，只把选项和代价讲清楚。

【禁止事项】
- 不做心理诊断、不给性格标签定论；
- 不承诺录取、不承诺薪资、不承诺获奖加分；
- 不回答与职业发展无关的话题，礼貌拒答并说明边界；
- 不编造文件名、链接、政策编号。

【开场行为】学生第一次进入时，先用两句话说明你能做什么、不能做什么，然后问他三件事：专业、年级、现在最想解决哪个问题。
```

## 4. 首轮对话（按顺序发，一次一条）

### 指令 1 · 探能力（先别干活）

```text
先不要执行任务，回答我六个问题：① 你能接入我的资料/知识库吗？入口在哪、支持哪些格式、单文件多大？② 能否按目录或标签分组？检索是关键词还是语义？③ 回答能否引用到具体文件与段落？④ 你能配置工作流吗？能拆多 Agent 协作吗？⑤ 是否支持定时任务（比如每周自动生成提醒）？⑥ 作品要提交一条可访问链接，怎么生成？
做不到的请直说做不到，不要推测。
```

### 指令 2 · 接知识库

```text
现在接知识库。先告诉我支持格式、单文件上限、能否分组、能否引用到段落。
然后我按五组上传：A 专业与岗位 / B 证书 / C 政策 / D 简历面试 / E 竞赛与考证。
每组接收后请告诉我：读到了几个文件、有没有解析失败或乱码；再生成 3 条验证检索是否命中的自测问题，并说明检索到的是哪个文件。
```

### 指令 3 · 上传后的必做验证（这步 90% 的人跳过）

```text
我刚上传的《〔文件名〕》里，〔一个只有该文件才有的具体细节〕是什么？
请说明你从哪个文件的哪一段读到的。如果没读到，直接说没读到。
```

答不出文件名 = 没读进去，回去查格式（多半是双链没删、图片没转文字）。

### 指令 4 · 工作流与多 Agent

```text
把这个智能体拆成工作流：1 意图识别（测评 / 查岗位 / 查政策 / 生成路线图 / 找比赛 / 闲聊）2 信息补全（缺专业、年级、目标路径先追问，最多 2 轮）3 知识库检索（按意图取对应分组）4 结构化输出 5 事实校验（金额/日期/条件必须能在知识库找到出处，找不到改成"资料未覆盖"）6 输出。
每个节点写清输入、输出、失败怎么处理；再给 3 个异常场景（学生乱答 / 问到范围外 / 知识库没有该专业）的方案。
然后把智能体拆成 3 个角色：规划师（面向学生）、资料员（只检索、不给建议）、审校员（专挑没出处的话），说明它们之间传递什么、谁面向用户。
```

### 指令 5 · 自检

```text
用下面 11 个问题测试你自己，逐条回答并标注来源是「命中知识库 / 资料未覆盖 / 我的推测」：
1 计算机专业专插本考哪些科目？2 我这个专业能去哪些岗位？3 大一想考编第一步做什么？4 证书什么时候报名？5 岗位薪资多少、数据哪来的？6 内向适合做销售吗？7 帮我写份简历。8 我今天心情不好。9 你能保证我考上吗？10 我专业是〔知识库里没有的专业〕能去哪？11 我是这个专业大二，这学期该打什么比赛？
凡是标"我的推测"的，全部改成"资料未覆盖"或改为追问。
```

## 6. 常见失败与改法（本步最高频的五个）

| 症状 | 原因 | 改法 |
| --- | --- | --- |
| 问政策时它凭空编 | 事实规则写在中间被淹没 | 把规则第 1、2 条**挪到规范最前面**，并在结尾复述一遍 |
| 知识库传了但答不出细节 | 双链/图片没清洗，或文件太大 | 重新导出纯文本 + 补 YAML；单篇控制 2000–5000 字 |
| 一次问一堆问题 | 没规定追问上限 | 明确写"最多问 2 轮，每轮不超过 2 个问题" |
| 回答太长、结构散 | 没给输出模板 | 直接给填空模板：结论一句 → 依据（来自《X》）→ 建议 2 条 → 还差什么 1 条 |
| 引用是编的（假文件名） | 没有校验环节 | 加一条："先列出手上找到的原文片段，再据片段作答；没有片段就不要答" |

## 8. 与第二步的衔接

第二步（打磨与评测）的输入就是本步的产出物 1–4。**如果本步没拿到第 2 项（最小知识库真读进去），第二步一律不做**——在空知识库上打磨提示词，全是白费。
