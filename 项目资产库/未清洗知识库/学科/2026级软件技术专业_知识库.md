# 第一部分  使用说明

## 一、这份知识库是什么

它是「路书」智能体的第一份事实来源，只装一所学校、一个专业、一份官方文件里的内容，并把每条内容都钉在具体页码上。目标很单一：**让学生问到的每一个事实，都能指回原文；问不到的，老实说没有。**

正文按学生真实会问的顺序排：这个专业是什么（第二部分）→ 能去什么岗位、要什么能力（第三部分）→ 考什么证（第四部分）→ 学什么课（第五部分）→ 怎么才能毕业（第六部分）→ 哪些问题这份文件答不了（第七部分）。

## 二、能答什么

| 学生的问题 | 对应部分 |
| --- | --- |
| 这个专业学几年、招什么人、属于什么大类 | 第二部分 |
| 毕业能做什么岗位、从什么岗位做起、往上走是什么 | 第三部分 |
| 某个岗位要什么能力、对应哪几门课 | 第三部分 |
| 能考哪些证、哪个证对应哪个岗位 | 第四部分 |
| 这个专业有哪些课、某门课到底学什么 | 第五部分 |
| 毕业要多少学分学时、实习多久、要几个证 | 第六部分 |
| 学校有什么实训室、能不能安排实习 | 第六部分 |

## 三、不能答什么（这部分比「能答什么」更重要）

| 答不了的 | 原因 | 该找谁 |
| --- | --- | --- |
| 薪资、起薪、涨薪空间 | 全文没有任何薪资数字 | 招生就业处；或另采可查来源的统计数据 |
| 专插本、考编的政策与条件 | 方案的路径只写了就业 | 招生就业处、教务处 |
| 证书报名时间、费用、通过率 | 方案只给了证书名称、颁证单位、等级 | 教务科研处、继续教育学院 |
| **每门课在第几学期开** | 《教学进程表》是附件，未随本文件提供 | 教务处（这是最该补的一份） |
| 企业真实招聘要求（JD） | 方案写的是学校培养口径，不是企业口径 | 招生就业处、合作企业 |
| 转专业、奖助学金、学分置换细则 | 方案只写「另行通知」 | 学生工作处、教务处 |

以上问题，智能体必须回答「现有资料未覆盖」，并给出建议确认部门，**不得用通用常识补充，不得给估算区间**。

## 四、引用与作答规则

1. **先检索再作答**：回答前先取回切片原文，用原文组句；没有命中就说「现有资料未覆盖」。
2. **带页码引用**：格式为《2026级软件技术专业人才培养方案》P3｜岗位能力晋升路径，与附录 A 的编号一一对应。
3. **数字与政策必带出处**：涉及金额、日期、报名条件、名额、政策条款，必须写明文件名与生效日期。
4. **政策类固定结尾**：以上信息来自《文件名》，生效日期〔日期〕，请以官方最新通知为准。本文件未标注生效日期，表述为「2026 级适用，文件未标注生效日期」。
5. **缺口优先**：命中第七部分的主题，直接按缺口口径回答，不要绕。
6. **口径冲突先声明**：原文有三处前后不一致，见第七部分第三节；引用岗位清单时以表 1、表 3 为准。
7. **禁用绝对化表述**：保证、一定、百分百、稳过。

## 五、这份文档怎么用

| 用法 | 怎么做 |
| --- | --- |
| 人工查阅 / 评审 | 直接读本文，或看「知识库浏览.html」（可搜索、可筛选、一键复制带页码引用） |
| 智能体接入 | 用 chunks/software-technology-2026.jsonl（74 条切片）或 seed/seed_knowledge.sql（可直接 psql 执行） |

切片字段与《路书_全栈技术文档》第 5 节的 knowledge_doc / knowledge_chunk 对齐：chunk_code（业务编号）、seq（文档内顺序）、breadcrumb（层级）、content（检索正文）、page_from / page_to（页码）、topic（主题）、fact_type（事实 / 边界声明 / 说明 / 规则 / 依据 / 元数据）、tags、applies_to（岗位名，可直接做岗位过滤）。

## 六、维护约定

- **时效**：校验满 12 个月后，回答末尾强制加「请以官方最新通知为准」。
- **换版**：拿到新版培养方案时，新增 docId 与切片，**不要就地改旧内容**，否则回答不了「我们入学时是不是这么规定的」。

## 3. 培养目标（P5）

本专业为广东省升级高水平专业群专业，以立德树人为根本，培养能够践行社会主义核心价值观，德智体美劳全面发展，具有一定科学文化水平，良好的人文素养、科学素养、数字素养、职业道德、创新意识、爱岗敬业的职业精神和精益求精的工匠精神，较强的就业创业能力和可持续发展的能力，掌握本专业知识和技术技能，具备职业综合素质和行动能力，**面向粤港澳大湾区软件与信息服务领域**，掌握软件产品**前端开发、服务端开发、测试与维护、移动应用开发**等知识和技术技能的高素质技能人才。

## 4. 培养规格

### 4.1 素质结构（P6）

1. **思想品德素质**：正确的世界观、人生观、价值观；爱国主义精神、社会责任感；职业道德与职业操守；组织观念、集体意识和团队合作精神。
2. **身心素质**：健康体魄、心理和健全人格；掌握基本运动知识和 1—2 项运动技能；稳定向上的情感力量、坚强恒久的意志力量。
3. **职业素质**：恪守诚信原则与行业法规，严守商业机密与用户隐私，尊重知识产权，履行数据安全责任；精益求精的工匠精神，追求代码规范性与系统稳定性；主动跟踪技术前沿（如云原生、AI）；高效参与跨职能协作，清晰撰写技术文档。
4. **综合素养**：数字公民素养，识别并抵制不良信息；绿色计算意识（节能降耗、资源集约）；跨文化交流基础能力，可对接粤港澳大湾区跨境项目需求；终身学习习惯；正确劳动观。

### 4.2 知识结构（P6）

1. **工具性知识**：英语、AI 大模型应用等。
2. **专业技术知识**：面向对象程序设计基础理论、数据库设计与应用、主流 Java 开发平台相关知识、软件测试技术和方法、软件项目开发与管理知识，以及软件开发相关国家和国际标准。
3. **人文社科知识**：思想政治理论、形势与政策、中华优秀传统文化。
4. **自然科学知识**：计算机数学等。

### 4.3 能力结构（P6—P7）

1. **学习能力**：用合适工具方法搜索、收集、评价和运用信息，持续学习。
2. **实践能力**：读懂软件需求分析报告和项目建设方案；计算机软硬件系统安装、调试、维护；简单算法的分析和设计，能用 HTML5、Java 等编程实现；数据库设计、应用与管理；软件界面设计、桌面及 Web 应用开发；软件测试、项目文档撰写和售后技术支持；初步具备企业级应用系统开发能力。
3. **适应能力**：独立生活、团队协作、人际交往与沟通；判断力、自律能力、自我评价能力和接受他人评价的承受力。

## 5. 专业群定位（P3）

以软件技术为核心，打通"网络基础设施 → 系统平台运维 → 应用软件研发 → 数据价值化 → 数字内容呈现"的专业群全产业链、专业链、人才链，服务新一代信息技术产业集群。

专业群对应岗位群：系统运维、软件开发、数据分析、交互设计。

# 第七部分  资料缺口清单

## 一、影响核心功能的缺口（优先补）

### 1. 《教学进程表》缺失 —— 直接影响"分学期路线图"

方案正文第十一部分写"详见《专业人才培养方案教学进程表》"，但附件未随本文件提供（P25）。
后果：

- 不知道每门课在**第几学期**开；
- 不知道每学期**学分/学时**分布；
- 无法判断"某门课什么时候上"，因此**不能仅凭本库生成准确的按学期清单**。

可做的替代：按课程模块的先修关系给出"建议学习顺序"，但必须明确告诉学生"具体开课学期以教务处《教学进程表》为准"，不得把建议顺序说成学校安排。

### 2. 三条路径只覆盖了"就业"

| 路径 | 本库覆盖情况 |
| --- | --- |
| 就业 | 覆盖：岗位群、职业能力、对应课程、证书、实习安排 |
| 专插本（专升本） | **完全未覆盖**：无对口本科专业、无考试科目、无报考条件与时间、无录取数据 |
| 考编（公务员/事业单位） | **完全未覆盖**：无岗位专业限制、无考试科目、无报名条件 |

后果：涉及"专插本""考编"的问题一律答"现有资料未覆盖"，并建议向**招生就业处 / 教务处**确认，不得用通用常识或记忆中的政策作答。

### 3. 薪资数据缺失

方案中没有任何薪资数字。`salary_stat` 表需要的 `p25/p50/p75 + sample_size + source_url` 本库都提供不了。

后果：任何薪资问题（起薪多少、某岗位能拿多少）只能答"现有资料未覆盖"。**不得给区间估值。**
