# 第一部分  使用说明

## 一、这份知识库是什么

它是「路书」智能体的第一份事实来源，只装一所学校、一个专业、两份官方文件里的内容，并把每条内容都钉在具体页码上。目标很单一：**让学生问到的每一个事实，都能指回原文；问不到的，老实说没有。**

正文按学生真实会问的顺序排：这个专业是什么（第二部分）→ 能去什么岗位、要什么能力（第三部分）→ 考什么证（第四部分）→ 学什么课（第五部分）→ 怎么才能毕业（第六部分）→ 哪些问题这两份文件答不了（第七部分）→ **每门课什么时候上、什么时候实习、考证排在哪学期（第八部分）**。

第八部分是 v0.2 新增的，也是「路书」能不能生成按学期路线图的关键：没有它，清单只能按课程模块给建议；有了它，清单可以直接写「第 3 学期上 Web 前端框架应用，一周 8 节，考试课」。

## 二、能答什么

| 学生的问题 | 对应部分 |
| --- | --- |
| 这个专业学几年、招什么人、属于什么大类 | 第二部分 |
| 毕业能做什么岗位、从什么岗位做起、往上走是什么 | 第三部分 |
| 某个岗位要什么能力、对应哪几门课 | 第三部分 |
| 能考哪些证、哪个证对应哪个岗位 | 第四部分 |
| 这个专业有哪些课、某门课到底学什么 | 第五部分 |
| **这门课第几学期上、一周几节、怎么考** | **第八部分** |
| **我这学期要上什么课、大概多忙** | **第八部分第 3 节** |

## 三、不能答什么（这部分比「能答什么」更重要）

| 答不了的 | 原因 | 该找谁 |
| --- | --- | --- |
| 薪资、起薪、涨薪空间 | 两份文件全文没有任何薪资数字 | 招生就业处；或另采可查来源的统计数据 |
| 专插本、考编的政策与条件 | 方案的路径只写了就业 | 招生就业处、教务处 |
| 证书报名时间、费用、通过率 | 方案只给了证书名称、颁证单位、等级 | 教务科研处、继续教育学院 |
| **具体开课日期、周次起止、校历** | 进程表只给「学期 + 周学时 + 周数」，没有日历日期 | 教务处（校历） |
| **实习企业的具体名单、岗位、名额、待遇** | 方案只写「软通动力等企业」与 6 个月 | 二级学院实习管理老师 |
| **某学期每门课各占几个学分** | 进程表只给分学期**周学时**，学分按课程整体计 | 教务处 |
| 企业真实招聘要求（JD） | 方案写的是学校培养口径，不是企业口径 | 招生就业处、合作企业 |
| 转专业、奖助学金、学分置换细则 | 方案只写「另行通知」 | 学生工作处、教务处 |

以上问题，智能体必须回答「现有资料未覆盖」，并给出建议确认部门，**不得用通用常识补充，不得给估算区间**。

> **v0.2 变更说明**：v0.1 中「每门课在第几学期开」曾列为最大缺口，现已由《附件4 教学进程表》闭合，相关答案见第八部分。原缺口条目在第七部分保留，标注为「已闭合」，以便追溯。

## 四、引用与作答规则

1. **先检索再作答**：回答前先取回切片原文，用原文组句；没有命中就说「现有资料未覆盖」。
2. **带页码引用**：培养方案写《2026级软件技术专业人才培养方案》P3｜岗位能力晋升路径；进程表写《教学进程表》J-P2｜专业核心课程。与附录 A 的编号一一对应。
3. **数字与政策必带出处**：涉及金额、日期、报名条件、名额、政策条款，必须写明文件名与生效日期。
4. **政策类固定结尾**：以上信息来自《文件名》，生效日期〔日期〕，请以官方最新通知为准。两份文件均未标注生效日期，表述为「2026 级适用，文件未标注生效日期」。
5. **缺口优先**：命中第七部分的主题，直接按缺口口径回答，不要绕。
6. **口径冲突先声明**：培养方案内部有三处不一致（见第七部分第三节）；两份文件之间有八处不一致（见第八部分第 6 节）。引用岗位清单以表 1、表 3 为准；引用开课学期一律以进程表为准。
7. **开课学期只有一个来源**：任何「第几学期上」的回答，只能来自第八部分，**不得用课程模块顺序或先修关系倒推**（进程表原文未标注先修关系）。
8. **禁用绝对化表述**：保证、一定、百分百、稳过。

## 五、这份文档怎么用

| 用法 | 怎么做 |
| --- | --- |
| 人工查阅 / 评审 | 直接读本文，或看「知识库浏览.html」（可搜索、可筛选、一键复制带页码引用） |
| 智能体接入 | 用 chunks/software-technology-2026.jsonl（74 条切片）＋ chunks/software-technology-2026-jx.jsonl（29 条进程切片），或 seed/seed_knowledge.sql（可直接 psql 执行） |
| 岗位库、匹配模块 | 用附录 B 的岗位表，或 data/careers.json（字段更全） |
| **分学期路线图** | **只用第八部分第 3 节「按学期拆解」，这是唯一带开课学期的事实来源** |
| 二次维护 | 改 jsonl 后跑 tools/build_seed.py 重新生成 SQL；浏览页与切片同源 |

切片字段与《路书_全栈技术文档》第 5 节的 knowledge_doc / knowledge_chunk 对齐：chunk_code（业务编号）、seq（文档内顺序）、breadcrumb（层级）、content（检索正文）、page_from / page_to（页码）、topic（主题）、fact_type（事实 / 边界声明 / 说明 / 规则 / 依据 / 元数据）、tags、applies_to（岗位名，可直接做岗位过滤）。新增的进程切片额外带 `term`（1–6，开课学期）字段，用于按学期过滤。

## 六、维护约定

- **时效**：校验满 12 个月后，回答末尾强制加「请以官方最新通知为准」。
- **换版**：拿到新版培养方案或新版教学进程表时，新增 docId 与切片，**不要就地改旧内容**，否则回答不了「我们入学时是不是这么规定的」。
- **双源并存**：培养方案管「学什么、为什么学」，进程表管「什么时候学、考什么、几周」。两者冲突时**排课以进程表为准**，培养目标与岗位能力以培养方案为准。
- **已闭合的第一优先补料**：《2026 级软件技术专业教学进程表》已于 v0.2 并入。
- **下一优先补料**：校历（开课日期/周次起止）、分学期学分拆分、岗位实习企业名单与名额。

## 4. 培养规格

### 4.1 素质结构（P6）

1. **思想品德素质**：正确的世界观、人生观、价值观；爱国主义精神、社会责任感；职业道德与职业操守；组织观念、集体意识和团队合作精神。
2. **身心素质**：健康体魄、心理和健全人格；掌握基本运动知识和 1—2 项运动技能；稳定向上的情感力量、坚强恒久的意志力量。
3. **职业素质**：恪守诚信原则与行业法规，严守商业机密与用户隐私，尊重知识产权，履行数据安全责任；精益求精的工匠精神，追求代码规范性与系统稳定性；主动跟踪技术前沿（如云原生、AI）；高效参与跨职能协作，清晰撰写技术文档。
4. **综合素养**：数字公民素养，识别并抵制不良信息；绿色计算意识（节能降耗、资源集约）；跨文化交流基础能力，可对接粤港澳大湾区跨境项目需求；终身学习习惯；正确劳动观。

### 4.2 知识结构（P6）

1. **工具性知识**：英语、AI 大模型应用等。
2. **专业技术知识**：面向对象程序设计基础理论、数据库设计与应用、主流 Java 开发平台相关知识、软件测试技术和方法、软件项目开发与管理知识，以及软件开发相关国家和国际标准。
3. **人文社科知识**：思想政治理论、形势与政策、中华优秀传统文化。
4. **自然科学知识**：计算机数学等。

### 4.3 能力结构（P6—P7）

1. **学习能力**：用合适工具方法搜索、收集、评价和运用信息，持续学习。
2. **实践能力**：读懂软件需求分析报告和项目建设方案；计算机软硬件系统安装、调试、维护；简单算法的分析和设计，能用 HTML5、Java 等编程实现；数据库设计、应用与管理；软件界面设计、桌面及 Web 应用开发；软件测试、项目文档撰写和售后技术支持；初步具备企业级应用系统开发能力。
3. **适应能力**：独立生活、团队协作、人际交往与沟通；判断力、自律能力、自我评价能力和接受他人评价的承受力。

## 5. 专业群定位（P3）

以软件技术为核心，打通"网络基础设施 → 系统平台运维 → 应用软件研发 → 数据价值化 → 数字内容呈现"的专业群全产业链、专业链、人才链，服务新一代信息技术产业集群。

**四条可以直接说的时间结论**：
1. **前端**：入学就有课，第 3 学期是分水岭（框架课 8 节/周 + 实训 2 周）。
2. **后端**：第 2 学期的 Java 程序设计是核心方向里唯一的考试课，第 3 学期 Java 框架接上。
3. **测试**：正式测试课第 3 学期才开、第 4 学期集中（8 节/周 + 2 周实训）。想走测试，前两学期要自己先把编程和 Linux 稳住。
4. **鸿蒙/移动端**：第 4 学期才开 HarmonyOS 应用开发，第 5 学期元服务。前两年不要因为「没鸿蒙课」以为方向不通。
